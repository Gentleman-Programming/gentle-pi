# Exploration: Consume gentle-ai release artifacts instead of hand-copying

> **Reconciled 2026-08-01** against the initiative handoff `gentle-ai-pi-release-artifact-plan.md`
> (decision register D1–D12). This document is **consumer-side (gentle-pi) only**. Provider work
> lives in gentle-ai's `publish-gentle-ai-release-artifacts`; Wave 1 host behavior lives in
> gentle-pi's `gentle-ai-main-behavior-parity`.
>
> The earlier revision of this file contained verified research **and** eight conclusions now proven
> wrong. Superseded conclusions are recorded in §2 rather than silently deleted, so a later reader
> can tell "we never knew that" apart from "we knew that and it was wrong".

## 1. Recommendation (lead with the answer)

gentle-ai publishes **one platform-independent, signed, self-describing assets archive** per release,
inside the existing `checksums.txt` + minisign envelope. gentle-pi consumes it at **two distinct
moments** and never re-authors the format:

| Moment | Runs where | Consumes | Evidence class |
|---|---|---|---|
| **Pack time** | gentle-pi CI / `prepack` | checked-in mirrors + lock derived from the pinned release; generated baselines; vendored shared skills | offline, deterministic, no network |
| **Install time** | end-user machine, `postinstall` | signed binary **and** the same signed assets archive, published as one atomic bundle | live signed release |

Everything gentle-pi keeps checked in is a **mirror derived one-way** from a pinned provider release,
bound by a canonical lock. Every per-PR check runs offline against those mirrors. Only an explicit
pin-bump job downloads.

- `lib/native-review-cli.ts::NATIVE_CLI_CONTRACTS` is a 12-row frozen table, one row per gentle-ai

## 6. The two consumption moments

They have different inputs, different evidence classes, and different failure modes. Conflating them
was error S-prev; the design must keep them separate.

| | **Pack time (vendoring)** | **Install time (extraction)** |
|---|---|---|
| Trigger | gentle-pi CI on every PR; `prepack` before `npm publish` | `postinstall` on the end-user machine |
| Input | checked-in mirrors + canonical lock (offline) | downloaded signed `checksums.txt`, minisign signature, assets archive |
| Trust source | the lock, itself derived from a verified release | live signature verification + digest match |
| Output | npm tarball contents: `contracts/`, `docs/`, generated `lib/` baselines, vendored skills | `.gentle-ai/v<version>/` atomic bundle: binary + assets under one integrity manifest |
| Network | **none**, except an explicit pin-bump job | required unless explicitly skipped |
| Failure mode | drift gate fails CI, naming exact files; never hand-edit generated output to force green | fail closed before publish; preserve or restore the prior complete bundle |

## 7. The hard boundary

Automatic parity **stops** at the line between "data that describes what the provider supports" and
"code that knows what to do with a new capability".

- **Consumable**: contract JSON schemas/fixtures, semantic snapshot name lists (operations, gates,
  projections, schemas, features), docs, checksums, portable skill markdown bodies (with an explicit
  overlay).
- **Never consumable**: if the provider adds a 14th operation or a new mandatory field on `start/v2`,
  `lib/review-integration-v2.ts` still needs a human to write the TypeScript branch. The mechanism
  makes the drift **detectable and actionable at build/CI time**; it cannot generate the decoder. An
  unmapped operation must stop generation with a message naming the operation and the decoder work
  required — never make an unknown operation appear supported because a snapshot listed it.

## 8. Compatibility by surface (D9)

| Surface | Rule | Consumer behavior |
|---|---|---|
| Required operations | Floor, additions open | Verify all required exist. Generate known mappings; fail actionably on an added operation needing unmapped client behavior. |
| Required schemas | Floor, additions open | Verify all required exist; preserve provider files through mirrors and drift gates. |
| Gates | Required floor | Decode unknown added strings safely, verify the floor, then narrow internal use to supported required gates. *(shipped in #263)* |
| Projections | Required floor | Same as gates. *(shipped in #263)* |
| **Mandatory features** | **Exact / rejected** | Reject unknown mandatory additions. The provider advertises `unknown_mandatory: "reject"`. |
| Optional features | Provider policy | Ignore unsupported unknown optional entries only where the declared policy permits. |

## 9. Platform model (D5)

| Platform | Binary provenance | Assets provenance | Result |
|---|---|---|---|
| Linux | signed platform binary archive | the common signed assets archive | atomic bundle binds both provenances |
| macOS | signed platform binary archive | the common signed assets archive | atomic bundle binds both provenances |
| Windows | exact-tag Go SumDB source-build verification | **the same** common signed assets archive | atomic bundle binds two distinct trust paths |

One atomic bundle and one canonical integrity manifest cover both, retaining distinct fields: binary
method/identity, binary digest or SumDB evidence, assets release/tag/archive identity, archive and
tree digests, and the release-artifact contract major + layout version. A failure in either path
prevents publication and preserves or restores the prior complete bundle.

## 10. Offline mirror and lock contract (D12)

gentle-pi checks in a **complete** provider-derived mirror plus one canonical lock:

| Lock field group | Binds |
|---|---|
| Release identity | repository, tag, semantic version, immutable commit |
| Contract identity | contract/schema ID and **major** version, layout version |
| Archive identity | assets archive name and its digest from the signed checksums |
| Tree identity | canonical non-recursive tree digest over sorted entries |
| Canonical entries | confined relative path, entry type, normalized mode, content digest |
| Generated outputs | digests of every file the generators emit |

Every per-PR check runs **offline** against mirrors + lock. Only a pin-bump job downloads. A drift
gate names exact files and never accepts a hand-edited generated or vendored file.

## 11. Evidence classes: S versus R (D4, D11)

| Class | Source | May prove | May **not** prove |
|---|---|---|---|
| **S** — bootstrap snapshot | local provider branch, `goreleaser --snapshot`, `dist/` (unsigned, not uploaded) | contract/layout/parser/extraction/install/generator development behavior | release authenticity, pin acceptance, final provenance |
| **R** — live signed release | stable immutable release: downloaded checksums + minisign + archive | final release identity, authenticity, package pin, production acceptance | anything outside the declared release contract |

S unblocks consumer development immediately — gentle-pi does **not** sit idle waiting for R — but no
S result may be relabeled as R, and no mutable provider `main` binary substitutes for R.

## 12. Repository-local delivery (D6)

```text
gentle-ai tracker:  A1 -> A2 -> A3 -> merge -> publish/verify R
                                                     |
                                                     v  (immutable release = the only bridge)
gentle-pi tracker:              P1 -> P2 -> P3 -> P4 -> merge

direct to gentle-pi main (already landed): #262, #263
```

No child PR crosses repositories. `repository_dispatch` becomes meaningful only after P4's receiver
workflow reaches gentle-pi's default branch; future automated bump PRs target `main`.

## 13. Packaging options (resolved)

| Option | Verdict |
|---|---|
| (i) Add assets to the four existing per-platform archives | **Rejected.** Duplicates identical platform-independent bytes four times and gives the Windows path nothing. |
| (ii) Separate platform-independent assets archive with no goos/goarch axis | **Selected.** One download regardless of platform; serves the Windows source-build path; clean split between the artifact that *runs* and the artifact that *declares*. |
| (iii) Fetch contracts from the tagged git repo at install time | **Rejected.** Breaks the trust model: nothing minisign-signed, requires git-protocol network access, weaker offline story. |

Provider-side confirmation that goreleaser's single `checksum:` block covers every declared archive
is a **provider (A2)** empirical task, not a consumer assumption.

## 15. Ready for proposal

**Yes.** Scope is bounded to the consumer, the two consumption moments are separated, the eight
superseded conclusions are recorded with their replacements, and the already-shipped quick wins are
excluded. Remaining unknowns are design-phase items with named owners, not scope ambiguities.
